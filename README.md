# 냉톡

> 대화로 관리하는 냉장고와 레시피

냉톡은 1인 가구가 냉장고 재고를 일일이 외우거나 목록부터 확인하지 않아도, 먹고 싶은 메뉴와 상황을 말하면 현재 가진 재료로 실행 가능한 한 끼를 함께 결정해 주는 Android·웹 서비스입니다.

Wanted AI Championship 2026 출품을 목표로 개발하고 있습니다.

## 해결하려는 문제

1인 가구는 구매한 식재료의 양과 소비 시점을 지속해서 관리하기 어렵습니다. 기존 냉장고 관리 앱은 재고 목록 입력에, 일반 레시피 서비스는 정해진 레시피 제공에 집중하는 경우가 많습니다.

냉톡은 다음 과정을 하나의 대화 흐름으로 연결합니다.

1. 구매내역 또는 자연어로 냉장고 재고 등록
2. 소비기한이 가까운 재료 우선 확인
3. 먹고 싶은 메뉴·시간·보유 조리도구를 반영한 레시피 상담
4. 요리 완료 후 실제 사용량만 재고에서 차감

## 핵심 기능

- **대화형 메뉴 상담**: 사용자가 원하는 메뉴와 조리 시간을 말하면 현재 재고에 맞는 레시피 한 가지를 제안하고 후속 대화로 수정합니다.
- **임박 재료 우선 안내**: 권장 소진일이 가까운 재료를 홈에서 먼저 보여주며 화면 높이에 따라 최대 6개까지 표시합니다.
- **구매내역 기반 재고 등록**: 배달의민족 장보기·쿠팡·마켓컬리 주문내역과 범용 전자영수증의 텍스트를 분석하는 흐름을 제공합니다.
- **자연어 직접 등록**: `두부 300g, 계란 10개, 소비기한은 9월 15일`처럼 여러 식품을 한 번에 입력할 수 있습니다.
- **재고 정렬과 수정**: 남은 소비기한 순 또는 한국어 이름순으로 확인하고, 화면과 채팅에서 수량을 수정합니다.
- **조리도구 반영**: 냄비·프라이팬·전자레인지·에어프라이어 등 사용자가 등록한 조리도구로 실행 가능한 레시피만 설계합니다.
- **알레르기 사전 반영**: 설정에 등록된 알레르기 항목을 추천 전에 확인합니다.
- **조리 타이머**: 레시피 단계의 시간 버튼으로 웹 내부 타이머를 실행하며 Android 시스템 타이머 연결을 지원할 예정입니다.
- **요리 완료와 재고 차감**: 사용량을 확인한 뒤 한 번의 작업으로 재고를 차감하고 완료 레시피를 보관합니다.
- **독립 게스트 체험**: 심사위원마다 별도의 익명 사용자와 10종의 샘플 재고를 제공하도록 설계했습니다.

## 대표 사용자 흐름

```text
로그인
  → 구매내역 또는 자연어로 재고 등록
  → 먹고 싶은 메뉴를 채팅으로 요청
  → 현재 재고·소비기한·알레르기·조리도구를 반영한 레시피 확인
  → 단계별 조리 및 타이머 사용
  → 사용량 확인
  → 요리 완료와 재고 차감
```

## 현재 구현 상태

| 구분 | 상태 |
| --- | --- |
| Expo 기반 Android·웹 공용 UI | 구현 및 브라우저 검수 완료 |
| 로그인 화면과 6개 하단 탭 | 구현 완료 |
| 10종 샘플 재고·임박 재료·정렬 | 로컬 동작 완료 |
| 레시피 상세·타이머·재조리·재고 차감 | 로컬 동작 완료 |
| Supabase 스키마·RLS·게스트 시드 migration | 초안 구현, 실제 프로젝트 연결 대기 |
| Supabase 익명 로그인·원격 재고 | 연결 진행 예정 |
| Google 로그인 | OAuth 설정 후 연결 예정 |
| GPT 대화·검색·레시피 재설계 | OpenAI API 서버 연동 예정 |

현재 화면에 표시되는 레시피와 재고는 핵심 동작을 검증하기 위한 로컬 샘플입니다. 실제 AI·클라우드 기능이 연결되기 전까지 이를 생성형 AI 결과로 표시하지 않습니다.

## AI 활용 방식

냉톡은 MVP에서 OpenAI GPT와 Responses API를 유일한 생성형 AI 제공자로 사용할 계획입니다.

- 주문내역·자연어 식품 입력의 구조화
- 사용자의 재고 관련 발화 해석
- 메뉴 의도와 임박 재료를 고려한 대화
- 만개의레시피 우선 검색과 필요 시 YouTube·일반 웹 검색 확장
- 검색 근거를 현재 재고·알레르기·조리도구에 맞게 재설계

수량 계산, 알레르기 최종 검사와 재고 변경은 AI가 데이터베이스를 직접 수정하지 못하도록 결정적 서버 코드와 트랜잭션으로 분리합니다.

## Codex와의 제작

이 프로젝트는 **OpenAI Codex를 기획·설계·개발 협업 도구로 사용**했습니다.

Codex는 대회 규정 조사, 제품 요구사항과 기술 설계 문서화, 와이어프레임 및 UI 구현, 테스트 작성, 코드 검증과 개발 기록 정리에 활용되었습니다. 서비스의 주요 기능 범위와 UX·데이터·안전 정책은 사용자가 직접 검토하고 결정했으며, 그 개입 내역은 [`HUMAN-IN-THE-ROOF.md`](HUMAN-IN-THE-ROOF.md)에 기록합니다.

## 기술 스택

- **클라이언트**: Expo SDK 55, React Native, Expo Router, TypeScript
- **대상 플랫폼**: Android, Web
- **백엔드**: Supabase Auth, Postgres, Row Level Security, Edge Functions
- **AI**: OpenAI Responses API
- **Android OCR**: 온디바이스 ML Kit Text Recognition 적용 예정
- **웹 배포**: EAS Hosting 예정
- **테스트**: Node.js test runner, TypeScript type check

## 프로젝트 구조

```text
mobile/                 Expo Android·웹 앱
mobile/src/domain/      재고 차감·정렬·레이아웃 등 순수 도메인 로직
mobile/src/features/    냉톡 화면과 상호작용
mobile/src/services/    Supabase 인증·세션·환경 설정 adapter
supabase/migrations/    데이터베이스 스키마·RLS·서버 함수
tests/                  도메인·설정·세션 회귀 테스트
docs/                   기획서·PRD·TRD·결정 및 작업 규칙
```

## 로컬 실행

### 준비 사항

- Node.js
- pnpm

### 설치 및 웹 실행

```bash
cd mobile
pnpm install
pnpm web
```

Supabase 환경값이 없으면 로컬 검증 모드로 실행됩니다. 실제 프로젝트를 연결할 때는 `mobile/.env.example`을 참고해 `mobile/.env.local`을 만들고 Project URL과 publishable key를 입력합니다.

### 테스트

저장소 루트에서 실행합니다.

```bash
npm test
node mobile/node_modules/typescript/bin/tsc --noEmit -p mobile/tsconfig.json
```

## 보안과 개인정보 원칙

- OpenAI API 키와 Supabase secret key를 앱 번들·저장소·문서에 넣지 않습니다.
- 클라이언트에는 RLS로 보호되는 Supabase publishable key만 사용합니다.
- 구매내역 원본과 OCR 원문은 필요한 처리 시간보다 오래 보관하지 않습니다.
- 모든 재고 변경은 사용자 확인과 서버 검증을 거칩니다.
- 게스트 데이터는 사용자별로 격리하고 마지막 활동 후 7일이 지나면 정리하도록 설계합니다.
