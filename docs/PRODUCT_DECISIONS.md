# 냉톡 제품 결정 기록

이 문서는 프로젝트에서 확정된 교차 기능 제품 결정을 보존한다. 작업할 기능과 관련된 항목만 선택적으로 읽고, 상세 사용자 요구사항은 `docs/PRD.md`, 기술 설계는 `docs/TRD.md`를 함께 참조한다.

## 확정된 제품 기준

- 최종 서비스명은 `냉톡 — 대화로 관리하는 냉장고와 레시피`다. 2026-09-08 기획 완료 및 개발 전환 승인.
- 2026-09-01 사용자가 현재 홈·채팅·재고·레시피·설정 와이어프레임의 구조와 탐색 방식을 기획 기준으로 승인했다.
- 핵심 사용자는 퇴근 후 메뉴 결정을 어려워하고 식재료를 낭비하기 쉬운 1인 직장인이다.
- Android 앱과 심사용 웹을 Expo 기반 단일 코드베이스로 제공한다.
- 심사용 웹은 Expo web export를 EAS Hosting 무료 플랜에 배포하고, 인증·Postgres·Storage·Edge Functions는 Supabase에서 운영한다. 심사 기간에는 Supabase Pro를 사용해 비활성 자동 중지를 방지하고 OpenAI API는 Supabase Edge Function에서만 호출한다. 배포 후 서비스는 사용자의 로컬 컴퓨터와 독립적으로 작동한다.
- MVP에서는 별도 도메인을 구매하지 않는다. EAS Hosting이 발급하는 무료 `*.expo.app` production URL을 웹 서비스와 고정 `/install` 설치 안내 페이지에 사용하고, QR 코드는 이 설치 안내 페이지를 가리킨다. 커스텀 도메인은 정식 서비스 전환 후 선택적으로 검토한다.
- Android 심사용 앱은 EAS Build의 `distribution: internal` 프로필로 서명된 설치용 APK를 생성하고 공유 URL로 제공한다. 웹 링크를 기본 체험 경로로 유지하며 APK 링크와 QR 설치 안내를 함께 제출한다. Play Console 내부 테스트와 GitHub Releases는 MVP의 APK 배포 필수 경로로 사용하지 않는다.
- 백엔드는 Supabase를 사용하고, 일반 사용자는 Google 로그인, 심사위원은 더미 데이터가 복제되는 독립 게스트 세션으로 진입한다.
- 인증되지 않은 첫 실행에는 홈이 아니라 전용 로그인 화면을 표시한다. 화면 중앙에 `게스트 로그인(심사)`과 `Google 로그인` 두 버튼을 제공하며, 인증과 초기화가 성공한 뒤에만 홈으로 이동한다. 유효한 로그인 세션은 앱·웹 재실행 시 자동 복원하고 설정에서 명시적으로 로그아웃하면 로그인 화면으로 돌아간다. 7일 비활성 정리로 삭제된 게스트나 갱신할 수 없는 세션은 다시 로그인해야 한다.
- Google 로그인과 게스트 초기화가 성공하면 별도의 온보딩·체크리스트·`냉톡 시작하기` 화면 없이 바로 홈으로 진입한다. 일반 사용자는 알레르기·조리도구·재고를 각 기능 화면에서 필요할 때 직접 등록한다.
- 게스트 챗봇은 고정 응답 데모가 아니라 일반 사용자와 동일한 AI 대화·검색·레시피 재설계 파이프라인을 사용한다. 심사위원의 후속 입력을 계속 처리하고, 요리 완료 시 게스트 전용 재고를 실제 트랜잭션으로 차감한다. 각 게스트는 최소 10종의 재료·조미료가 복제된 독립 pantry를 가지며 새우 알레르기가 기본 설정된다.
- 일반 사용자의 각 채팅 메시지는 생성 시점부터 정확히 30일간 보관한 뒤 자동 삭제하며 새 대화가 이어져도 기존 메시지의 만료 시각을 연장하지 않는다. AI 문맥과 요약에도 최근 30일 범위만 사용한다. 설정에서는 확인 후 즉시 실행되는 `채팅 기록 전체 삭제`만 제공하고 MVP의 개별 대화·메시지 삭제는 제외한다. 채팅이 삭제되어도 확정된 재고 변경 이력과 완료 레시피는 독립 기록으로 유지하며, 게스트 채팅은 게스트 전체 데이터의 7일 비활성 정리 정책을 따른다.
- 게스트 재고 10종은 `두부 300g`, `달걀 10개`, `돼지고기 앞다리살 300g`, `김치 500g`, `양파 2개`, `대파 2대`, `감자 3개`, `간장 500ml`, `된장 500g`, `식용유 500ml`로 확정한다. 권장 소진일은 접속일 기준 상대 날짜로 생성하고 데모 데이터임을 표시한다.
- 심사위원은 공용 게스트 계정을 공유하지 않는다. `signInAnonymously()`로 접속자마다 고유 Supabase 익명 사용자와 JWT를 발급하고, 버전이 있는 게스트 시드를 해당 `auth.uid()` 소유로 트랜잭션 복제한다. RLS로 다른 게스트 접근을 차단하며 마지막 활동 후 7일이 지나면 앱 데이터와 익명 계정을 정리한다. 익명 가입에는 CAPTCHA와 rate limit을 적용한다.
- 메인 화면은 상단 2/3에 권장 소진일이 임박한 재료를 보여주고, 하단 1/3을 좌우로 나눠 `구매내역 등록`과 `오늘 뭐 먹지?`를 배치한다. 임박 재료는 화면 높이에 따라 4개에서 최대 6개까지 자동 확장하며 행동 카드 제목은 기기 폭에 맞춰 축소하더라도 한 줄을 유지한다.
- 하단 내비게이션은 `홈`, `채팅`, `재고`, `레시피`, `조리도구`, `설정`의 여섯 항목으로 구성한다.
- 홈을 제외한 모든 주요 섹션의 좌상단에는 둥근 사각형 안의 홈 아이콘 버튼을 제공한다.
- 자동 등록은 `배달의민족 장보기`, `쿠팡`, `마켓컬리`의 온라인 구매내역 캡처와 종이 영수증 레이아웃의 전자영수증 캡처를 지원한다. 구매내역에 포함된 상품 이미지는 분석하지 않고 OCR로 추출한 텍스트만 구조화한다. 실물 식재료 사진과 종이 영수증 사진은 MVP 범위에서 제외하고 직접 입력으로 보완한다.
- 구매내역 개인정보는 최소 보존한다. MVP의 Android·웹은 원본 이미지를 인증된 `purchase-ocr` Edge Function의 요청 메모리에서만 처리하며 Storage·DB·로그에 기록하지 않는다. OpenAI 요청은 `store:false`로 전송하고 OCR 원문과 구조화 검수 초안도 등록 확정·취소 후 폐기하며, 최종 재고 lot만 보존한다.
- MVP의 Android·웹 구매내역 OCR은 OpenAI `gpt-5.6-luna` 비전 입력으로 통일한다. `detail: original`, reasoning `none`, strict JSON schema를 사용하고 사용자별 하루 10회·이미지 5MB 제한을 적용한다.
- AI 실행 구조는 하이브리드로 유지한다. 구매내역 글자 인식·상품 구조화·자연어 대화·검색·레시피 재설계는 OpenAI가 담당하고, 지원 단위·보수적 권장 소진일·알레르기·조리 안전·재고 트랜잭션은 결정적 코드가 담당한다.
- MVP의 생성형 AI 제공자는 OpenAI 하나만 사용하고 GPT 계열 모델을 OpenAI Responses API로 호출한다. Gemini 등 다른 생성형 AI 제공자는 MVP 실행 경로와 장애 대체 경로에 포함하지 않는다.
- 클라우드 AI는 작업별 모델 라우팅을 사용한다. `gpt-5.6-luna`가 상품·조리도구 구조화, 재고 발화 해석과 단순 대화를 처리하고, `gpt-5.6-terra`는 검색 근거 판단·레시피 재설계·복잡한 후속 대화에만 사용한다. Luna의 신뢰도가 기준 미만일 때만 요청당 한 번 Terra로 승격한다.
- 캡처 업로드 후 입력 원천을 자동 판별하고, 신뢰도가 낮을 때만 사용자에게 쇼핑몰 또는 전자영수증 유형을 선택하도록 요청한다.
- 구매내역 인식 결과는 위험도 기반 일괄 검수로 처리한다. 사용자에게는 재고명·수량·권장 소진일만 수정 가능한 입력란으로 보여주고 판정·비고·OCR 원문은 내부 상태로 유지한다. 확인 필요 항목은 최상단에 빨간 테두리로 배치하고 경고 문구를 표시하며, 사용자 최종 확정 전에는 재고 DB를 변경하지 않는다.
- 구매내역 일부만 인식되면 성공한 품목과 사용자의 수정값을 보존하고 실패한 품목·필드만 재입력 또는 재분석한다. 전체 OCR 실패 시 다른 캡처 선택과 직접 입력을 제공한다.
- 재고 페이지 상단에는 `재고 등록` 버튼을 두고 홈의 구매내역 등록 팝업을 공용 에셋으로 재사용한다. 팝업의 `직접 입력`은 별도 자연어 입력 팝업을 열며, 사용자는 여러 식품의 이름·용량·소비기한을 쉼표 또는 줄바꿈으로 한 번에 입력할 수 있다. `식품 등록` 시 AI가 항목을 분리·구조화하고 결정적 검증을 거쳐 재고 카드로 등록한다. 불확실한 항목만 확인을 요구하고 성공한 등록에는 실행 취소를 제공한다.
- 재고는 구매 lot 단위로 저장하고 화면에서는 합산해 보여준다. 차감은 권장 소진일이 가까운 lot부터 처리한다.
- 재고 화면의 기본 정렬은 남은 권장 소진일 순이며 사용자는 한국어 이름순으로 전환할 수 있다. 홈은 9:20 Android 웹 프레임 안에서 임박 재료와 행동 영역을 2:1로 배분하고, 임박 행은 남은 수량 뒤에 굵은 날짜를 표시한다. 조리도구 카드는 3열로 표시하고 긴 이름을 줄바꿈한다.
- 재고 수량은 사용자가 이해하는 원본 수량·단위와 계산용 표준 수량·단위를 함께 저장한다. 근거가 있는 경우에만 `g`, `ml`, `개`로 변환하고, 변환 근거가 없으면 원본 단위를 유지한 채 자동 합산·차감하지 않는다.
- 조리도구는 사용자가 자연어 한 줄로 직접 입력하고, 원문과 AI가 정규화한 종류·용량·특징을 함께 저장한다. 레시피는 보유 조리도구로 실행 가능하거나 안전하게 변형 가능한 경우에만 제시한다.
- 레시피 원천은 `만개의레시피` 검색·참조를 1순위로 사용하고, 적절한 근거를 찾지 못하면 YouTube와 일반 웹(Google 검색 경험)으로 확장한다. AI는 확인된 출처를 바탕으로 재고, 요청, 알레르기, 조리도구, 조리시간과 난이도에 맞게 새 표현으로 변형한다.
- 만개의레시피 전체 데이터를 크롤링하거나 자체 레시피 DB로 복제하지 않는다. 레시피 요청이 생길 때만 OpenAI Responses API의 `web_search`를 `10000recipe.com` 도메인으로 제한해 주문형 검색한다. 구체적인 메뉴 요청은 메뉴명을 우선하고, 막연한 요청은 권장 소진일이 가장 가까운 핵심 재료 1~2개를 검색어로 사용한다. 만개의레시피 검색은 검색어 수정 포함 최대 2회로 제한하고 적합한 근거가 없으면 YouTube와 일반 웹으로 확장한다.
- YouTube fallback도 별도 YouTube Data API 없이 OpenAI Responses API의 `web_search`를 `youtube.com` 도메인으로 제한해 요청당 최대 1회 수행한다. 공개 제목·설명·검색 페이지에서 필요한 조리 근거를 확인할 수 있을 때만 출처로 사용하고, 영상 내용을 직접 시청·전사한 것처럼 간주하지 않는다. 텍스트 근거가 부족하면 일반 웹 검색으로 확장한다.
- 만개의레시피의 본문·이미지·데이터를 사전 허락 없이 복제하거나 대량 수집·재배포하지 않는다. 자동 접근은 약관·robots 정책·별도 이용 허락 또는 공식 연동 수단이 확인된 범위에서만 구현하며, 최종 레시피에는 참고 출처 링크와 변주 사실을 표시한다.
- 레시피 변주는 `근거 기반 재설계형`으로 한다. 동일 메뉴가 없어도 양념 비율·재료별 처리·투입 순서처럼 필요한 조리 원리를 나눠 검색하고, 허용된 범위에서 최대 3개 출처의 공통 원리와 핵심 안전 조건을 확인한 뒤 재료 구성과 단계를 새 표현으로 설계한다. 상세 화면에는 대표 출처 1개를 바로 표시하고 추가 출처는 펼쳐서 확인하게 하되 변경점 요약은 사용자에게 별도 노출하지 않는다.
- 근거 부족은 위험도에 따라 처리한다. 육류·생선·달걀·해산물의 가열 안전처럼 위해 가능성이 높은 재료·단계는 신뢰 가능한 근거가 없으면 생성하지 않고 다른 메뉴를 제안한다. 양념 조합, 채소 추가, 인분 조정 등 저위험 변경만 AI가 근거 범위 안에서 재설계할 수 있다.
- 추천 우선순위는 요청 구체성에 따라 바꾼다. 구체적인 메뉴 요청은 사용자 의도를 먼저 지키고, 막연한 요청은 임박 재료와 재고 활용도를 먼저 본다. 알레르기·식품 안전·보유 조리도구·사용자가 지정한 시간은 항상 필수 조건으로 적용한다.
- 초기 추천은 최상위 후보 1개만 제시하고, 사용자의 후속 채팅에 따라 같은 제안을 수정한다. 추천 가능한 정보가 있으면 바로 제안하며, 안전·실행 가능성·재고 변경에 꼭 필요한 경우에만 한 번에 하나의 확인 질문을 한다.
- 알레르기 설정은 기본 빈 목록이며 전체 법정 목록이나 체크리스트를 사용자에게 미리 제시하지 않는다. 사용자가 실제 알레르기만 자유 텍스트로 항목별 등록·삭제하고, 빈 상태는 `등록된 알레르기 없음`으로 표현한다. 내부 정규화·동의어 사전은 등록된 항목에 대해서만 활성화해 파생 재료를 검사하며 등록되지 않은 항목을 임의로 사용자 알레르기로 간주하지 않는다. 추천 전에 등록 목록을 AI 입력에 포함하고 생성 후 규칙 기반 검증도 통과해야 한다. 채팅마다 다시 묻지 않으며 심사위원 게스트에는 `새우`만 기본 등록한다.
- 사용자가 지정한 메뉴에 필수 재료가 없으면 누락 이유를 설명하고 `필수 재료 구매 후 원하는 메뉴 만들기`와 `현재 재료로 의도를 살린 다른 메뉴 만들기`를 함께 제시한다. 안전하고 정체성을 해치지 않는 대체재가 있을 때만 대체 선택지를 추가하며, 사용자 선택 전에는 레시피를 확정하지 않는다.
- 채팅에서 레시피를 제시할 때는 전체 화면 상세로 보여주고, `채팅으로 돌아가기`와 `요리 완료`를 제공한다.
- 채팅 탭 진입 시에는 채팅 화면만 열고, 대화 속 `레시피 전체 보기`를 눌렀을 때만 전체 화면 상세를 연다.
- `요리 완료`를 누른 레시피만 제공일과 함께 레시피 탭에 카드로 저장하며, 카드를 누르면 전체 화면 상세로 다시 연다.
- 레시피 상세를 포함한 모든 주요 화면은 내용 스크롤을 지원하되 스크롤 바는 시각적으로 숨긴다.
- 조리 단계에 시간이 명시되면 해당 단계 아래에 타이머 버튼을 제공한다. Android는 시스템 타이머, 웹은 실제 내부 타이머를 제공한다.
- MVP에서 평가·즐겨찾기는 제외하되, 저장 레시피 재조리와 재고 재차감은 포함한다. 매번 새 조리 세션으로 재검증·차감 확인을 거치고 같은 요청의 중복 차감을 차단한다.
- 단일 재료 정정은 즉시 반영 후 취소 기능을 제공하고, 여러 재료가 바뀌는 레시피 차감은 미리보기와 사용자 확정 후 실행한다.
- 레시피는 조미료도 가능한 한 큰술·작은술과 `ml`·`g`처럼 계량 가능한 양으로 제시한다. 수치와 환산 근거가 있는 사용량은 요리 완료 시 차감 미리보기에 자동 포함하고, `약간`·`적당량` 또는 환산 근거가 없는 항목만 사용자가 수정하거나 제외하게 한다. 근거 없는 추정 차감은 하지 않는다.
- 레시피를 열어 조리를 시작하면 임시 조리 세션을 만든다. 조리 중 `간장 한 큰술 더 넣었어`, `방금 추가한 것 취소해` 같은 대화는 세션의 사용량 원장만 갱신하며 실제 재고는 바꾸지 않는다. `요리 완료`의 최종 미리보기와 사용자 확정 뒤에만 전체 사용량을 한 트랜잭션으로 차감한다.
- 앱이 종료돼도 진행 중 조리 세션은 시작 후 12시간 동안 복구할 수 있다. 재진입 시 `진행 중인 요리`에서 `이어하기`와 `조리 취소`를 제공하고, 12시간이 지나면 세션만 만료하며 재고는 차감하지 않는다.
- 구매목록에 소비기한 텍스트가 있으면 공식 표시일 후보를 우선한다. 표시일이 없으면 정규화 재고명·보관 방법·포장 상태로 공용 `shelf_life_rules`를 먼저 조회하고, 활성 규칙이 없거나 확인 후 365일이 지난 항목만 OpenAI 웹 검색으로 보수적인 권장 기간과 출처를 확인한다. 검증된 HTTPS 출처가 있는 결과만 공용 DB에 저장하며 모든 사용자가 재사용한다.
- 계란·우유처럼 포장별 표시일 차이가 큰 품목은 직접 입력을 유도한다. 검색 근거를 확보하지 못하면 식품군별 짧은 fallback 기간을 적용해 `확인 필요`로 표시하고 공용 DB에는 저장하지 않는다. 공식 표시일과 사용자 입력 날짜는 항상 우선하며 모든 권장 소진일은 사용자가 수정할 수 있다.
- 구매내역 캡처는 웹 파일 탐색기와 Android 사진 보관함에서 한 번에 최대 10장을 선택할 수 있다. R1~R5 샘플도 복수 선택하며 이미지별 하루 한도 1회를 차감해 순차 처리하고 일부 실패 시 성공 결과와 사용자 수정값을 보존한다.
- Android는 임박 재료 푸시 알림, 웹은 앱 내 배너를 제공한다. 알림은 재고에 남은 품목을 대상으로 D-7·D-3·D-1에 발송하며, 같은 날 대상은 하나로 묶고 사용자별 하루 최대 한 번으로 제한한다.
- 임박 알림의 기본 발송 시간은 사용자 현지 시간 오후 6시이며 설정 화면에서 변경할 수 있다. 시간대가 바뀌면 다음 발송부터 새 현지 시간 기준을 적용한다.
- 임박 알림을 누르면 대상 재료를 다시 조회·검증한 뒤 해당 재료가 맥락으로 포함된 채팅을 연다. 챗봇은 임박 재료를 알려주고 사용자가 원하는 메뉴·맛·시간을 물어 레시피 상담으로 바로 이어간다.
