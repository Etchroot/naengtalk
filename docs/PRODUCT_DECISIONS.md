# 냉톡 제품 결정 기록

이 문서는 프로젝트에서 확정된 교차 기능 제품 결정을 보존한다. 작업할 기능과 관련된 항목만 선택적으로 읽고, 상세 사용자 요구사항은 `docs/PRD.md`, 기술 설계는 `docs/TRD.md`를 함께 참조한다.

> 구현 경계(2026-09-27): 아래 결정 중 Google OAuth, 첫 Android APK, 시스템 알림·시스템 타이머, 12시간 조리 세션 복구는 아직 출시되지 않은 후속 범위다. 현재 심사용 production 경로는 게스트 인증, 웹 내부 타이머와 즉시 요리 완료 트랜잭션이다.

## 확정된 제품 기준

- 최종 서비스명은 `냉톡 — 대화로 관리하는 냉장고와 레시피`다. 2026-09-08 기획 완료 및 개발 전환 승인.
- 2026-09-01 사용자가 현재 홈·채팅·재고·레시피·설정 와이어프레임의 구조와 탐색 방식을 기획 기준으로 승인했다.
- 핵심 사용자는 퇴근 후 메뉴 결정을 어려워하고 식재료를 낭비하기 쉬운 1인 직장인이다.
- Android 앱과 심사용 웹을 Expo 기반 단일 코드베이스로 제공한다.
- 심사용 웹은 Expo web export를 EAS Hosting 무료 플랜에 배포하고, 인증·Postgres·Storage·Edge Functions는 Supabase에서 운영한다. 심사 기간에는 Supabase Pro를 사용해 비활성 자동 중지를 방지하고 OpenAI API는 Supabase Edge Function에서만 호출한다. 배포 후 서비스는 사용자의 로컬 컴퓨터와 독립적으로 작동한다.
- MVP에서는 별도 도메인을 구매하지 않는다. EAS Hosting이 발급하는 무료 `*.expo.app` production URL을 웹 서비스와 고정 `/install` 설치 안내 페이지에 사용하고, QR 코드는 이 설치 안내 페이지를 가리킨다. 커스텀 도메인은 정식 서비스 전환 후 선택적으로 검토한다.
- Android 심사용 앱은 EAS Build의 `distribution: internal` 프로필로 서명된 설치용 APK를 생성하고 공유 URL로 제공한다. 웹 링크를 기본 체험 경로로 유지하며 APK 링크와 QR 설치 안내를 함께 제출한다. Play Console 내부 테스트와 GitHub Releases는 MVP의 APK 배포 필수 경로로 사용하지 않는다.
- production 웹은 `https://naengtalk.expo.app`에 먼저 배포해 사용자가 실시간으로 기능·UI를 검수한다. Android는 EAS Update의 production 채널과 앱 버전 기반 runtime을 미리 설정하되, 첫 APK는 웹 디자인이 확정된 뒤 빌드한다.
- 백엔드는 Supabase를 사용하고, 일반 사용자는 Google 로그인, 심사위원은 더미 데이터가 복제되는 독립 게스트 세션으로 진입한다.
- 2026-09-21 공용 권장 소진일 기준은 사용자가 제공한 116행 엑셀의 원문·기관명 출처를 보존한다. URL은 엑셀 출처와 수동 승인 `AI추정`에는 필수가 아니지만 새 웹 검색 결과에는 필수다. 소금은 100년, 엑셀에 없는 맛소금·허브솔트는 5년의 `AI추정` 관리값으로 둔다. 캐시/검증된 웹 근거가 없을 때만 일반 Terra 추정을 마지막 수단으로 사용하며 포장 표시일·사용자 입력일이 우선한다.
- 심사용 구매 예시는 R2를 제외하고 R1·R3·R4·R5만 `예시 1`~`예시 4`로 노출한다. 해당 캡처에 반복 등장하는 깻잎 무쌈·닭가슴살 치킨너겟·카레·양배추 샐러드 소스는 심사 흐름에서 빈 날짜가 되지 않도록 보수적인 수동 승인 `AI추정` 공용 규칙을 사용한다.
- 인증되지 않은 첫 실행에는 홈이 아니라 전용 로그인 화면을 표시한다. 화면 중앙에 `게스트 로그인(심사)`과 `Google 로그인` 두 버튼을 제공하며, 인증과 초기화가 성공한 뒤에만 홈으로 이동한다. 유효한 로그인 세션은 앱·웹 재실행 시 자동 복원하고 설정에서 명시적으로 로그아웃하면 로그인 화면으로 돌아간다. 7일 비활성 정리로 삭제된 게스트나 갱신할 수 없는 세션은 다시 로그인해야 한다.
- Google 로그인과 게스트 초기화가 성공하면 별도의 온보딩·체크리스트·`냉톡 시작하기` 화면 없이 바로 홈으로 진입한다. 일반 사용자는 알레르기·조리도구·재고를 각 기능 화면에서 필요할 때 직접 등록한다.
- 게스트 챗봇은 고정 응답 데모가 아니라 일반 사용자와 동일한 AI 대화·검색·레시피 재설계 파이프라인을 사용한다. 심사위원의 후속 입력을 계속 처리하고, 요리 완료 시 게스트 전용 재고를 실제 트랜잭션으로 차감한다. 각 게스트는 총 30종의 재료·조미료가 복제된 독립 pantry를 가지며 새우 알레르기가 기본 설정된다.
- 일반 사용자의 각 채팅 메시지는 생성 시점부터 정확히 30일간 보관한 뒤 자동 삭제하며 새 대화가 이어져도 기존 메시지의 만료 시각을 연장하지 않는다. AI 문맥과 요약에도 최근 30일 범위만 사용한다. 설정에서는 확인 후 즉시 실행되는 `채팅 기록 전체 삭제`만 제공하고 MVP의 개별 대화·메시지 삭제는 제외한다. 채팅이 삭제되어도 확정된 재고 변경 이력과 완료 레시피는 독립 기록으로 유지하며, 게스트 채팅은 게스트 전체 데이터의 7일 비활성 정리 정책을 따른다.
- 2026-09-20 게스트 시드 v2는 기존 품목을 포함해 한식 재료 총 30종이며 간장·설탕·소금·된장·고추장 등 기본 조미료는 고체 500g/액체 500ml로 제공한다. 기본 조리도구는 가스레인지·프라이팬·집게·뒤집개·용량별 냄비 3종 등을 포함한 16종이다. 기존 게스트 데이터는 자동 변경하지 않고 명시적 샘플 초기화 시에만 새 시드를 적용하되, 2026-09-21 승인된 소금의 고정 권장 소진일 `2127-03-20` 보정만 기존 게스트에도 일괄 적용한다.
- 2026-09-20 추가 결정: 심사용 시드의 `개`·`대` 단위 재료는 계란·무·양배추를 포함해 각각 10으로 제공하고, 조리도구 카드 이름은 18px로 표시한다. 이미 사용 중인 게스트 재고는 덮어쓰지 않는다. AI 추천이 재고 검증에서 탈락할 때는 구매 제한을 완화하지 않고 한 번 재작성한 뒤 명확한 실패 사유를 표시한다.
- AI 신규 생성·공유 기반 레시피는 외부 레시피 사이트를 출처로 주장하지 않는다. 공공 DB 기반 변형에만 해당 기관명을 설명에 표시하며, 기존 저장 레시피도 표시 시 같은 규칙을 적용한다.
- 심사위원은 공용 게스트 계정을 공유하지 않는다. `signInAnonymously()`로 접속자마다 고유 Supabase 익명 사용자와 JWT를 발급하고, 버전이 있는 게스트 시드를 해당 `auth.uid()` 소유로 트랜잭션 복제한다. RLS로 다른 게스트 접근을 차단하며 마지막 활동 후 7일이 지나면 앱 데이터와 익명 계정을 정리한다. 익명 가입에는 CAPTCHA와 rate limit을 적용한다.
- 메인 화면은 상단 2/3에 권장 소진일이 임박한 재료를 보여주고, 하단 1/3을 좌우로 나눠 `구매내역 등록`과 `오늘 뭐 먹지?`를 배치한다. 임박 재료는 화면 높이에 따라 4개에서 최대 6개까지 자동 확장하며 행동 카드 제목은 기기 폭에 맞춰 축소하더라도 한 줄을 유지한다.
- 2026-09-27 홈의 세 카드는 `새틴 냉장고 도어` 시각 방향을 사용한다. 부분 광택선은 제거하고 카드 테두리 안쪽 전체의 3px 흰색 림과 우하단 그림자로 돌출된 문 깊이를 표현한다. 상단은 연녹색, 구매 등록은 연베이지, 메뉴 상담은 밝은 새틴 하늘색을 사용한다. 상단 큰 카드의 하단과 두 행동 카드의 상단에는 오목한 가로 손잡이 이미지를 배치하고 두 행동 카드 손잡이는 위에서 아래로 잡아 여는 방향으로 상하 반전한다. 기존 2:1 정보 구조는 유지하되 공통 상단바를 약 70%로 축소해 확보한 공간을 하단 행동 카드에 배분한다. 모든 화면의 상단바 아래 첫 콘텐츠 간격은 16px 기준으로 통일하고 전역 캔버스와 함께 비례 축소한다. 현재는 로컬 미리보기 검수 단계이며 사용자 승인 전 production에 배포하지 않는다.
- 2026-09-27 작은 기기에서는 개별 텍스트를 줄바꿈하거나 홈을 스크롤시키는 대신 기준 360×800 앱 캔버스 전체를 균일하게 축소한다. 헤더·아이콘·텍스트·카드·여백·내비게이션의 상대 크기와 화면 구조를 모든 주요 탭에서 유지하며, 채팅 키보드가 열릴 때만 기존 결정대로 크기를 유지한 프레임을 위로 이동한다.
- 하단 내비게이션은 `홈`, `채팅`, `재고`, `레시피`, `조리도구`, `설정`의 여섯 항목으로 구성한다.
- 홈을 제외한 모든 주요 섹션의 좌상단에는 둥근 사각형 안의 홈 아이콘 버튼을 제공한다.
- 자동 등록은 `배달의민족 장보기`, `쿠팡`, `마켓컬리`의 온라인 구매내역 캡처와 종이 영수증 레이아웃의 전자영수증 캡처를 지원한다. 구매내역에 포함된 상품 이미지는 분석하지 않고 OCR로 추출한 텍스트만 구조화한다. 실물 식재료 사진과 종이 영수증 사진은 MVP 범위에서 제외하고 직접 입력으로 보완한다.
- 구매내역 개인정보는 최소 보존한다. MVP의 Android·웹은 원본 이미지를 인증된 `purchase-ocr` Edge Function의 요청 메모리에서만 처리하며 Storage·DB·로그에 기록하지 않는다. OpenAI 요청은 `store:false`로 전송하고 OCR 원문과 구조화 검수 초안도 등록 확정·취소 후 폐기하며, 최종 재고 lot만 보존한다.
- MVP의 Android·웹 구매내역 OCR은 OpenAI `gpt-5.6-luna` 비전 입력으로 통일한다. `detail: original`, reasoning `none`, strict JSON schema를 사용하고 사용자별 하루 10회·이미지 5MB 제한을 적용한다.
- AI 실행 구조는 하이브리드로 유지한다. 구매내역 글자 인식·상품 구조화·자연어 대화·검색·레시피 재설계는 OpenAI가 담당하고, 지원 단위·보수적 권장 소진일·알레르기·조리 안전·재고 트랜잭션은 결정적 코드가 담당한다.
- MVP의 생성형 AI 제공자는 OpenAI 하나만 사용하고 GPT 계열 모델을 OpenAI Responses API로 호출한다. Gemini 등 다른 생성형 AI 제공자는 MVP 실행 경로와 장애 대체 경로에 포함하지 않는다.
- 클라우드 AI는 작업별 모델 라우팅을 사용한다. `gpt-5.6-luna`가 상품·조리도구 구조화, 재고 발화 해석과 단순 대화를 처리하고, `gpt-5.6-terra`는 검색 근거 판단·레시피 재설계·복잡한 후속 대화에만 사용한다. Luna의 신뢰도가 기준 미만일 때만 요청당 한 번 Terra로 승격한다.
- 캡처 업로드 후 입력 원천을 자동 판별하고, 신뢰도가 낮을 때만 사용자에게 쇼핑몰 또는 전자영수증 유형을 선택하도록 요청한다.
- 구매내역 인식 결과는 위험도 기반 일괄 검수로 처리한다. 사용자에게는 재고명·수량·권장 소진일만 수정 가능한 입력란으로 보여주고 판정·비고·OCR 원문은 내부 상태로 유지한다. OCR 원문 근거가 없는 품목과 같은 이미지의 완전 동일 행은 제거한다. 필수값이 비었거나 형식이 잘못된 항목만 최상단에 빨간 테두리로 배치하며, 하나라도 남으면 등록을 차단한다. AI 신뢰도나 소비기한 fallback만으로 완전한 행을 빨간색으로 만들지 않는다.
- 구매내역 일부만 인식되면 성공한 품목과 사용자의 수정값을 보존하고 실패한 품목·필드만 재입력 또는 재분석한다. 전체 OCR 실패 시 다른 캡처 선택과 직접 입력을 제공한다.
- 재고 페이지 상단에는 `재고 등록` 버튼을 두고 홈의 구매내역 등록 팝업을 공용 에셋으로 재사용한다. 팝업의 `직접 입력`은 별도 자연어 입력 팝업을 열며, 사용자는 여러 식품의 이름·용량·소비기한을 쉼표 또는 줄바꿈으로 한 번에 입력할 수 있다. `식품 등록` 시 AI가 항목을 분리·구조화하고 결정적 검증을 거쳐 재고 카드로 등록한다. 불확실한 항목만 확인을 요구하고 성공한 등록에는 실행 취소를 제공한다.
- 재고는 구매 lot 단위로 저장하고 화면에서는 합산해 보여준다. 차감은 권장 소진일이 가까운 lot부터 처리한다.

- 구매내역 캡처는 웹 파일 탐색기와 Android 사진 보관함에서 한 번에 최대 10장을 선택할 수 있다. `예시 1`~`예시 4`도 복수 선택하며 이미지별 하루 한도 1회를 차감해 순차 처리하고 일부 실패 시 성공 결과와 사용자 수정값을 보존한다.
- 후속 알림 기능에서 Android는 임박 재료 푸시 알림, 웹은 앱 내 배너를 제공한다. 알림은 재고에 남은 품목을 대상으로 D-7·D-3·D-1에 발송하며, 같은 날 대상은 하나로 묶고 사용자별 하루 최대 한 번으로 제한한다.
- 임박 알림의 기본 발송 시간은 사용자 현지 시간 오후 6시이며 설정 화면에서 변경할 수 있다. 시간대가 바뀌면 다음 발송부터 새 현지 시간 기준을 적용한다.
- 임박 알림을 누르면 대상 재료를 다시 조회·검증한 뒤 해당 재료가 맥락으로 포함된 채팅을 연다. 챗봇은 임박 재료를 알려주고 사용자가 원하는 메뉴·맛·시간을 물어 레시피 상담으로 바로 이어간다.
