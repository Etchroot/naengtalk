# 냉톡 서비스 기획서

- 문서 상태: 기획 확정·개발 시작 승인
- 기준일: 2026-09-08
- 서비스명: 냉톡
- 부제: 대화로 관리하는 냉장고와 레시피
- 한 줄 소개: 냉장고 재고와 대화해 남김없이 나만의 한 끼를 만드는 1인 가구용 AI 냉장고 매니저

## 1. 기획 배경

1인 가구는 소량으로 다양한 식재료를 구매하지만, 남은 양과 권장 소진일을 계속 기억하기 어렵다. 기존 냉장고 관리 서비스는 재고 목록을 직접 확인하고 수정해야 하는 경우가 많고, 일반 레시피 서비스는 사용자가 실제로 가진 재료보다 정형화된 레시피 제공에 집중한다.

냉톡은 사용자가 재고를 외우거나 목록부터 확인하지 않아도, 먹고 싶은 메뉴와 상황을 말하면 현재 냉장고를 기준으로 실행 가능한 한 끼를 함께 결정하도록 돕는다.

## 2. 해결하려는 문제

- 냉장고에 무엇이 얼마나 남았는지 기억하기 어렵다.
- 식재료의 소비 가능 시점을 놓쳐 음식과 비용이 낭비된다.
- 일반 레시피는 보유 재료·남은 양·조리시간을 동시에 반영하지 못한다.
- 재고를 등록하고 사용량을 차감하는 과정이 번거로워 관리가 오래 지속되지 않는다.
- 먹고 싶은 메뉴에 핵심 재료가 없을 때 대체안과 구매 필요성을 함께 판단하기 어렵다.

## 3. 목표 사용자

### 핵심 사용자

- 혼자 거주하고 직접 장을 보며 간단한 집밥을 해 먹는 직장인
- 퇴근 후 메뉴 결정에 피로를 느끼는 사람
- 식재료를 자주 남기거나 권장 소진일을 놓치는 사람

### 사용자가 원하는 결과

> “내 냉장고를 일일이 확인하지 않고 말만 해도, 지금 먹고 싶은 한 끼를 만들 방법과 필요한 구매 항목을 바로 알고 싶다.”

## 4. 제품 콘셉트

냉톡은 레시피북이 아니라 대화형 냉장고 에이전트다.

- **대화 우선:** 메뉴, 시간, 난이도, 남은 재료를 자연어로 말한다.
- **재고 기반:** 구매 내역과 사용 확정을 재고에 연결한다.
- **근거 있는 맞춤 생성:** 전체 레시피를 수집하지 않고 요청 시점에 만개의레시피를 도메인 제한 검색한다. 구체적인 요청은 메뉴명, 막연한 요청은 가장 임박한 핵심 재료 1~2개를 우선 검색하고, 적절한 결과가 없으면 YouTube와 일반 웹으로 확장한 뒤 사용자의 재고와 상황에 맞게 새 레시피 표현으로 변형한다.
- **조리 원리 조합형 재설계:** 동일한 메뉴가 없어도 양념 비율, 재료별 처리와 투입 시점처럼 필요한 조리 원리를 나눠 검색한다. 최대 3개 출처의 공통 원리와 안전 조건을 확인한 뒤 재고·알레르기·조리도구·시간에 맞춰 재료 구성과 단계를 새로 설계하고 대표 출처를 공개한다.
- **위험도 기반 생성 제한:** 고위험 식재료의 가열·위생 단계는 근거가 있을 때만 사용하고, 근거가 부족하면 다른 메뉴로 전환한다. AI의 자유 재설계는 양념·채소·인분처럼 저위험 영역으로 제한한다.
- **낭비 방지:** 권장 소진일이 가까운 재료를 우선 활용하고 알림을 제공한다.
- **근거 있는 날짜 추정:** 공식 표시 소비기한을 우선하고, 날짜가 없는 식재료만 식약처·식품안전나라의 보관 원칙과 USDA FoodKeeper의 식품별 기간을 조합한 버전 관리 기준표로 계산한다. 범위는 짧은 값을 적용하고 `권장 소진일(추정)`로 구분한다.
- **맥락별 우선순위:** 구체적인 메뉴 요청은 먹고 싶은 의도를, 막연한 요청은 임박 재료 소진을 먼저 반영한다.
- **한 가지 제안:** 가장 적합한 메뉴 하나를 먼저 제시하고 사용자의 후속 대화로 수정한다.
- **사전 안전 설정:** 알레르기 설정은 기본 빈 상태이며 사용자가 실제 항목만 자유롭게 등록한다. 등록된 항목에 대해서만 내부 동의어·파생 재료 사전을 적용하고 모든 추천 전에 자동 검사한다.
- **현실적인 제안:** 필수 재료가 없으면 억지로 대체하지 않고 구매 여부를 묻는다.
- **실제 게스트 체험:** 심사위원도 고정 시나리오가 아닌 동일한 AI 챗봇과 재고 트랜잭션을 사용하며, 변경은 독립 게스트 냉장고에만 반영된다.
- **동시 심사 격리:** 심사위원마다 익명 사용자와 게스트 냉장고를 새로 만들고 RLS로 격리한다. 마지막 활동 후 7일이 지나면 임시 데이터를 정리한다.
- **하이브리드 AI:** Android의 민감한 구매내역 OCR은 기기에서 처리하고, 서버 규칙은 계산·안전을 통제하며, 클라우드 AI는 비정형 언어 이해와 레시피 재설계에 집중한다.
- **단일 생성형 AI 제공자:** MVP의 상품 구조화·대화·검색 판단·레시피 재설계는 OpenAI의 GPT 계열 모델과 Responses API로 구현하며 Gemini 등 별도 생성형 AI 제공자는 사용하지 않는다.
- **작업별 모델 라우팅:** 단순 구조화·분류는 `gpt-5.6-luna`, 검색 근거 판단·레시피 재설계는 `gpt-5.6-terra`를 사용하고 Luna 결과가 불확실한 경우에만 요청당 한 번 Terra로 승격한다.

## 5. 핵심 차별점

| 구분 | 일반 냉장고 관리 앱 | 일반 레시피 서비스 | 냉톡 |
| --- | --- | --- | --- |
| 시작점 | 재고 목록 | 레시피 검색 | 먹고 싶은 메뉴에 대한 대화 |
| 재고 입력 | 직접 입력 중심 | 제공하지 않음 | 구매내역 캡처 인식 + 사용자 검수 + 직접 입력 |
| 레시피 | 제한적 또는 없음 | 정형화된 레시피 | 현재 재고·소진 우선순위·시간에 맞춘 변형 |
| 재고 차감 | 사용자가 수동 수정 | 연결되지 않음 | 원본 단위와 계산 단위를 함께 보존하고 대화 또는 요리 완료 확인 후 자동 반영 |
| 부족 재료 | 별도 확인 | 장보기 목록 제공 가능 | 필수 재료의 구매 필요성을 대화로 확인 |
| 낭비 방지 | 만료 알림 중심 | 해당 없음 | 임박 알림과 레시피 추천을 연결 |

## 6. 대표 사용자 경험

1. 사용자가 온라인 구매내역 화면을 캡처해 올린다.
2. 냉톡이 상품명·옵션·수량·용량을 읽고, 표시일 입력이 필요한 품목과 기준표로 권장 소진일을 계산할 품목을 구분한다.
3. 모든 품목은 한 검수 화면에 자동 입력되며, 불확실한 필드만 강조된다. 사용자는 품목을 제외하거나 직접·채팅으로 수정한 뒤 한 번에 재고 등록을 확정한다.
4. 사용자는 `2.5L 냄비`, `1인용 에어프라이기`처럼 보유 조리도구를 자연어로 등록한다.
5. 저녁에 “20분 안에 얼큰한 걸 먹고 싶어”라고 말한다.
6. 냉톡은 메뉴명이 구체적이면 메뉴명과 조건으로, 요청이 막연하면 가장 임박한 재료 1~2개와 조건으로 만개의레시피를 주문형 검색한다. 검색어 수정까지 최대 2회 안에 적절한 근거를 찾지 못하면 YouTube와 일반 웹으로 확장한 뒤 현재 재고, 알레르기, 조리시간과 보유 조리도구를 고려한 레시피 하나를 제안한다.
7. 필수 재료가 부족하면 `구매 후 원하는 메뉴`와 `현재 재료로 의도를 살린 다른 메뉴`를 함께 보여주고 사용자가 선택하게 한다.
8. 사용자가 레시피를 열고 단계별 시스템 타이머를 사용한다.
9. 조리 중 “간장 한 큰술 더 넣었어”처럼 말하면 임시 조리 세션의 사용량만 갱신된다.
10. 앱이 닫히면 홈의 `진행 중인 요리`에서 12시간 동안 이어하거나 취소할 수 있다.
11. `요리 완료` 후 계량 가능한 재료·조미료의 최종 차감량을 확인한다. `약간`처럼 불확실한 항목만 수정하거나 제외하면 재고가 한 번에 갱신되고 레시피가 기록된다.

## 7. MVP 범위

### 포함

- Android 앱과 심사용 웹
- 첫 실행 전용 로그인 화면, Google 로그인과 심사위원용 익명 게스트 체험, 유효 세션 자동 복원과 설정 로그아웃
- Google 인증 또는 게스트 초기화 성공 후 별도 온보딩 없이 즉시 홈 진입
- 최소 10종 재료·조미료를 가진 수정 가능한 게스트 냉장고, 실제 후속 대화와 재고 차감
- 게스트 기본 재고: 두부·달걀·돼지고기 앞다리살·김치·양파·대파·감자·간장·된장·식용유
- 배달의민족 장보기·쿠팡·마켓컬리 구매내역 캡처의 텍스트 인식
- 종이 영수증 형식의 전자영수증 캡처 범용 인식
- Android 원본 이미지 비업로드와 웹 임시 이미지 즉시 삭제를 적용한 개인정보 최소 보존
- 직접 재고 입력·수정·삭제
- 재고 페이지의 공용 등록 팝업과 여러 식품을 한 번에 처리하는 AI 자연어 직접 입력
- 대화형 재고 조회와 단일 재료 수정
- 자연어 기반 조리도구 등록과 보유 도구 기반 레시피 필터링
- 재고·권장 소진일·선호 조건 기반 레시피 추천
- 만개의레시피 우선 검색과 YouTube·일반 웹 검색 fallback, 참고 출처 링크 표시
- 대표 출처 1개 상시 표시와 추가 출처 펼쳐보기
- 부족한 필수 재료의 구매안·대체 메뉴 병렬 제안
- 레시피 상세, 단계별 타이머, 요리 완료 후 재고 차감
- 조미료의 계량 단위 우선 제시와 불확실 사용량만 완료 시 확인
- 조리 중 사용량 변경의 임시 세션 기록과 완료 시 일괄 차감
- 중단된 조리 세션의 12시간 복구와 만료 시 재고 미차감
- 완료한 레시피 저장
- 설정의 빈 기본 목록, 알레르기 자유 입력·삭제와 등록 항목별 동의어 자동 검사
- Android 임박 알림과 웹 앱 내 배너
- D-7·D-3·D-1 단계별 임박 알림, 다수 재료 묶음과 하루 최대 1회 제한
- 현지 시간 오후 6시 기본 발송과 설정에서 알림 시간 변경
- 임박 알림에서 대상 재료가 전달된 채팅으로 바로 진입

### 제외

- 실물 종이 영수증 사진 OCR
- 식재료 실물 사진만으로 품목·중량을 자동 확정하는 기능
- iOS 전용 앱
- 식료품 자동 주문·결제
- 의료 목적의 영양 진단
- AI 판단만으로 실행되는 무확인 재고 변경

## 8. 해커톤 제출 전략

심사 시 핵심 시연은 `구매내역 등록 → 대화형 메뉴 요청 → 맞춤 레시피 → 요리 완료 → 재고 자동 차감`의 한 흐름으로 구성한다. 기획력과 AI 활용 적절성을 보여주기 위해 AI가 잘하는 비정형 입력 해석·상황별 변형과, 규칙 기반으로 통제해야 하는 재고 트랜잭션을 명확히 분리한다.

## 9. 핵심 성과 지표

- 첫 구매내역 등록 완료율
- 추천 레시피 상세 열람률
- 추천 대비 요리 완료율
- AI가 제안한 재고 변경의 사용자 승인률과 수정률
- 권장 소진일 임박 재료의 실제 사용률
- 게스트 사용자의 핵심 시연 흐름 완료율

## 10. 주요 위험과 대응

| 위험 | 대응 방향 |
| --- | --- |
| 구매내역 인식 오류 | 성공 결과와 사용자 수정값을 보존하고 실패한 필드만 재처리, 전체 실패 시 다른 캡처·직접 입력 제공 |
| 구매내역의 개인정보 노출 | Android는 원본 비업로드·비상품 텍스트 사전 제거, 웹은 비공개 임시 처리 후 즉시 삭제·1시간 강제 만료, OCR 원문 비영구 저장 |
| 소비 가능 시점의 개인차 | 구매목록에 실제 날짜가 있을 때만 공식 표시일로 사용하고, 그 외에는 보관 상태별 보수적 기준표와 사용자 수정 적용 |
| AI 레시피의 품질·안전 문제 | 만개의레시피 우선 검색 후 YouTube·일반 웹으로 근거를 확장하고, 출처·알레르기·가열 주의를 표시한 제한적 변형 적용 |
| 외부 레시피 저작권·약관 위반 | 본문·이미지·전체 DB를 복제하지 않고 출처명·제목·URL 중심으로 참조한다. 자동 접근은 이용 허락 또는 허용된 연동 수단이 확인된 범위로 제한한다. |
| 과도한 변주로 메뉴 정체성·안전 훼손 | 최대 3개 출처의 공통 조리 원리와 핵심 안전 조건을 잠그고, 변경 재료·수량·도구·단계는 서버 내부에서 구조화해 최종 검증한다. |
| 고위험 조리 근거 부족 | 육류·생선·달걀·해산물의 가열·위생 근거가 없으면 레시피 생성을 중단하고 근거가 확보된 다른 메뉴를 제안한다. |
| AI의 잘못된 재고 변경 | 구조화된 변경안 검증, 사용자 확인, 트랜잭션, 취소 기록 |
| 심사 링크 장애 | 웹 헬스체크, 게스트 데이터, 배포 상태 모니터링 |
| 운영비 증가 | 호출 단계 분리, 작은 모델 우선, 캐시와 사용량 제한 |

| 동시 게스트 데이터 충돌·남용 | 접속자별 익명 사용자·독립 시드·RLS 적용, CAPTCHA와 호출 제한, 7일 비활성 정리 |

## 12. 문서 갱신 원칙

2026-09-08 최종 반영: 웹 내부 타이머 포함, 평가·즐겨찾기 제외, 저장 레시피 재조리 및 재고 재차감 포함. 화면 제목은 굵게, 레시피명·제공일은 분리한다. 실제 게스트 시드는 최소 10종이다.

이 문서는 현재 합의된 기획 기준이다. 기획이 확정되거나 구현 결과가 달라지면 PRD·TRD·TODO·제출서류와 함께 갱신한다. 구현하지 않은 기능을 완료된 기능처럼 표현하지 않는다.
