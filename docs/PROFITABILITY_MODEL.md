# 냉톡 월간 수익성 계산기

작성·공식 단가 확인: 2026-10-11. AdMob 설정 전에 사용자 요청으로 만든 시나리오 도구다. 실제 계정 청구·광고 보고서를 연결하지 않으며 앱·광고 설정을 바꾸지 않는다.

## 실행

- `tools/profitability/index.html`을 일반 브라우저에서 열면 같은 폴더의 JS/CSS로 계산한다. 폴더 파일을 함께 보관한다.
- 브라우저에서 웹 주소로 보려면 저장소에서 `node tools/profitability/serve.mjs` 실행 후 `http://127.0.0.1:4187/` 접속. 현재 컴퓨터에서만 열리며 외부 공개 배포가 아니다.
- 서버는 계산기 HTML/JS/CSS 네 파일만 허용하고 저장소·환경 파일은 제공하지 않는다.
- 가정값은 해당 브라우저 localStorage에 저장한다. 초기화·JSON 내보내기를 제공한다. 입력은 외부로 전송하지 않는다.
- 검증: `node --test tools/profitability/model.test.mjs`.

## 배너 수익

현재 Android에는 홈·재고·완료 레시피에서 한 배너가 표시된다. 웹·상담·OCR 검수에는 광고가 없다. 화면 진입이나 동일 광고를 켜둔 매초에 대해 고정 금액을 받는 구조가 아니다. CPC·CPM 광고의 성과를 합친 eCPM으로 예상 매출을 계산한다. eCPM에 클릭 기반 수익이 포함되므로 클릭 수익을 별도로 더하지 않는다.

- 예상 매출 = 실제 표시된 노출 / 1,000 × eCPM.
- 가정 요청량 = MAU × 월 사용일 × Android 비율 × 광고 화면 체류 구간/일 × 구간당 요청 기회 × 요청 가능 비율.
- 예상 노출 = 요청량 × 매칭률 × 받은 광고 표시율.
- 새로고침 끔: 표시 시간이 양수인 구간마다 초기 요청 기회 1회 가정.
- 새로고침 켬: `ceil(표시 시간 / 주기)` 기회 가정. 정각 경계에서는 추가 노출이 아직 완료되지 않았다고 본다. 네트워크 지연·광고 로드 시간은 매칭·표시율로 단순화했다.
- 실제 SDK 새로고침은 배너가 보일 때만 발생한다. Google 최적화 주기는 고정값이 아니며 사용자 지정 30~150초 또는 끄기를 지원한다. 계산기의 주기는 실제 AdMob 설정을 변경하지 않는다.
- 테스트 모드는 매출 0. 현재 preview APK는 테스트 광고다. 출시 후에도 실제 매칭·노출·eCPM을 넣어야 한다.

공식 출처: [광고 CPC/CPM](https://support.google.com/admob/answer/3418058?hl=ko), [eCPM](https://support.google.com/admob/answer/15337570?hl=ko), [새로고침](https://support.google.com/admob/answer/3245199?hl=ko), [화면 표시 중 새로고침](https://developers.google.com/admob/android/banner), [테스트 광고](https://developers.google.com/admob/android/test-ads).

## 코드에 따른 비용 경로

| 사용자 작업 | AI 호출 | 기타 비용 |
| --- | --- | --- |
| 사진 OCR | 사진별 Luna 1회 + 소진일 조회 | Edge·Auth·DB·전송 |
| 직접 텍스트 등록 | Luna 1회 + 소진일 조회 | Edge·DB |
| 메뉴 추천·재추천 | Luna 분류 + Terra 개인화 또는 생성, 검증 실패 시 Terra 재작성 최대 1회 | Edge·DB 후보 조회·관측 기록 |
| 재고에 없는 재료를 지정한 메뉴 요청 | 최초 Luna 1회로 확인 팝업; 취소 시 종료, 확인 시 Luna 반복 없이 Terra 생성 | Edge 1회 추가·5분 일회용 확인 티켓 |
| 인사·재고 질문·채팅 소비/수량 변경 | Luna 분류 1회 | DB 확인·변경 |
| 채팅 재고 추가 | Luna 분류 + Luna 파싱 + 소진일 조회 | Edge 2회·DB |
| 직접 수정·삭제, 요리 완료, 공유 | AI 0회 | DB compute·전송·용량 |
| 로그인·계정 삭제 | AI 0회 | Auth 및 삭제 Edge |

근거: `supabase/functions/purchase-ocr/index.ts`, `inventory-parse/index.ts`, `menu-chat/index.ts`, `_shared/shelf-life-resolver.ts`, `mobile/src/features/NaengTalk.tsx`, `mobile/src/services/remote-inventory.ts`.

소진일 조회는 분석마다 고유 식품·보관·포장 조합의 캐시 누락을 3종씩 묶어 Terra 웹 검색한다. 검색으로 확인하지 못한 조합은 3종씩 Terra 추정한다. 검색 Responses 요청마다 도구 호출 최대 3회이며 도구 단가와 모델 토큰을 모두 더한다. 현재 명시 날짜가 있는 품목도 enrichment를 수행하므로 날짜 입력만으로 조회 비용을 0으로 계산하지 않는다.

묶음 기대값은 품목별 독립 적중을 가정한 이항 분포의 `E[ceil(누락 개수 / 3)]`다. 다른 사용자 요청을 월 단위로 합쳐 묶지 않는다. 품목 수·적중률은 세 등록 방식에 공통 적용하는 단순화이며 실제 품목별 캐시 변화는 반영하지 않는다. 소수 품목 수는 두 인접 정수 개수의 혼합으로 계산한다. 기능별 1회 AI 비용에는 소진일 비용을 배분하며, 월 합계 표에서는 중복 합산하지 않는다.

## 단가·가정·한계

- 공식 표준 API 가격/100만 토큰: Luna 입력 $0.20, 캐시 읽기 $0.02, 출력 $1.20; Terra 입력 $2, 캐시 읽기 $0.20, 출력 $12. 캐시 쓰기는 일반 입력의 1.25배. 모델 교체·긴 컨텍스트·별도 서비스 등급은 실제 단가를 다시 입력한다. 기본 토큰 길이는 긴 컨텍스트 기준 이하의 임의 추정이다. [Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra).
- 웹 검색 도구 $10/1,000회 + 검색 내용 입력 토큰. 검색 내용은 프롬프트 캐시 할인을 적용하지 않는다. [OpenAI 가격](https://developers.openai.com/api/docs/pricing).
- Supabase 기본값은 Pro $25, Auth 10만 MAU, Edge 200만 호출 포함 및 초과 단가를 사용했다. 이는 현재 계정 플랜 확인 결과가 아니다. DB/Storage/전송/Realtime·추가 compute와 EAS/Hosting/빌드/OTA·기타 비용을 수정할 수 있다. Free는 기본요금뿐 아니라 한도도 수정해야 하며 유료 초과분을 지원하지 않을 수 있다. [Supabase 가격](https://supabase.com/pricing), [청구와 포함량](https://supabase.com/docs/guides/platform/billing-on-supabase).
- 단순 DB 수정 1회마다 별도 정액 요금이 붙는다고 가정하지 않는다. 구매 사진은 영구 저장하지 않아 Storage 기본 사용량 0이다. 사진 업로드는 인바운드라 egress에 자동 포함하지 않는다.
- 모든 기능 사용량은 사용자당 **월** 평균. 광고 계산만 사용자당 월 사용일을 사용한다. OCR 10회/일, 파싱·상담 각 30회/일 제한 초과 가능성은 경고한다. 분포·사용자별 집중 사용까지 보장하지 않는다.
- 사용자 재시도 비율은 추가 요청/청구의 평균이며 자동 HTTP 재시도 구현을 의미하지 않는다. 레시피 재작성률과 별도다.
- 기본 eCPM $1, 환율 1,400원, 토큰·체류·적중·사용량은 실측이 없는 **예시**다. 국가 평균·보장 매출이 아니다. 세금·인건비·카드 수수료·일회성 가입료는 기본 미포함; 월 비용으로 반영하려면 기타 비용에 직접 입력한다.
- 사용자가 늘어도 사용자당 매출이 AI·기타 변동비보다 작으면 성장만으로 흑자가 되지 않는다. 첫 손익분기 MAU는 Auth·Edge·egress 포함량 경계를 반영하되, 이후 초과 단가 때문에 다시 적자가 될 수 있다. 검색 범위는 1,000만 MAU. 성장 그래프의 DB/Storage·기타 직접 입력 월 사용량은 고정된다.
- 예산은 화면 경고선일 뿐 실제 서버 호출·결제를 제한하지 않는다.
- menu-chat trace에는 모델별 실제 입력·출력 토큰이 있으나 캐시 상세가 없다. OCR·텍스트·소진일 검색의 토큰/도구 호출 계측은 현재 없으므로 계산기 가정으로 남긴다. 이후 계측을 추가하면 실측 평균으로 교체 가능하다.

기본 시나리오 (MAU 1,000, 월 사용일 12, OCR 4장·추천 8회/인·월 등): 광고 약 $18.47, AI 약 $246.26, 인프라 $25, 월 손익 약 -$252.79. 예측 가정을 설명하는 예시이며 실제 서비스 손익이라고 확정하지 않는다.

## 월간 냉톡 토큰 정책 검토 (2026-10-11)

사용자 확정 방향: 선택형 보상 광고 제외, API 토큰과 다른 냉톡 전용 사용권 단위, 사용자별 월간 무료 지급, 챗봇 입력만 차감하며 요청 유형에 따라 차감량 차등. 무료 1,000토큰으로 레시피 5회 + 채팅 재고관리 10회 조합을 기준으로 검토한다. 결제 구현·가격·아래 차감표는 아직 승인되지 않은 제안이다.

제안: 레시피 생성/재추천 160, 채팅 단순 재고 조회·소비·수량 변경 20, 채팅 재고 추가 60토큰. 기본 가정 원가가 각각 30.52원/0.84원/11.71원이므로 추가 등록을 가벼운 변경과 동일 20토큰으로 책정하지 않는다. 5회+10회 조합은 가벼운 재고관리 10회를 의미하며 재고 추가가 포함되면 횟수가 달라진다. 매월 1,000토큰은 이월 없이 갱신하는 안; 유료 잔액은 분리한다. 실패/자동 재작성은 고객에게 중복 차감하지 않는 안이며 운영자 원가에는 반영한다.

재고에 없는 사용자 지정 재료 확인은 최초 Luna 분류 뒤 Terra 호출 전에 멈춘다. `취소`는 추가 API 호출이 없고 향후 냉톡 토큰 원장에서도 비과금으로 분류한다. `계속 진행`은 일회용 티켓으로 Luna와 일일 횟수 증가를 반복하지 않고 Terra 단계로 이어진다. 현재는 냉톡 토큰 잔액·결제 원장이 구현되지 않았으므로 실제 차감이 발생하지 않으며, 위 내용은 향후 원장 계약이다.

초기 가격 제안은 세전 상품대금 $1당 1,000토큰. 한국에서 15% 서비스 수수료 등급에 등록하는 경우를 가정한다. 부가세·환전·환불·별도 결제 비용은 별도이며 실제 판매가·정산액 확정이 아니다. [Play 서비스 수수료](https://support.google.com/googleplay/android-developer/answer/112622?hl=ko).

환율 1,400원, 기존 토큰 가정, 재시도 추가 5%, 레시피 재작성 10% 포함 시 무료 5회+가벼운 관리 10회 원가 약169원/인·월. 추가 구매는 무료 잔액 밖에서 사용하고 전량 레시피에 쓰는 가정: $1당 1,000/1,500/2,000토큰의 유료 사용 AI 원가 약200/300/401원. 수수료 제외 정산 $0.85에서 AI 원가를 빼면 무료 사용자·서버를 지원할 잔액 약990/890/789원이다.

MAU 1,000, 모든 사용자가 무료 기준 조합 전량 사용, Supabase 월$25, 광고수익 0, 각 구매자가 매월 추가$1 한 번 구매·전량 사용, 다른 비용 제외라는 예시에서 1,000/1,500/2,000토큰 판매안의 필요한 구매 비율은 약20.6%/22.9%/25.8%다. 월 사진4장+직접 텍스트2회/인이 별도 무료로 유지되면 약27.9%/31.0%/34.9%로 올라간다. 무료 사용자 비용은 구매 비율이 낮으면 회수하지 못하며 구매 안 자체로 흑자를 보장하지 않는다. 무료 토큰을 전부 더 비싼 요청에 쓰는 경우 원가도 기준 조합보다 커진다.

채팅 외 OCR·직접 텍스트 분석도 API 비용이 들지만 냉톡 토큰을 차감하지 않는 요구이므로 별도 이용량 한도·월 운영 예산을 논의해야 한다. 실제 토큰/도구 원가를 계측해 가격·차감을 갱신하기 전까지 위 수치는 시나리오다.
