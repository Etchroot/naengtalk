# 레시피 검색·생성·공유 설계

## 범위와 현재 상태

- 공공 `recipe_catalog` 3개 테이블과 CSV 적재는 완료됐다. 현재 `menu-chat`은 아직 외부 레시피 웹 검색을 호출한다.
- 현재 `complete_recipe_cooking`은 요리 완료와 재고 차감, 개인 `public.recipes` 저장을 한 트랜잭션에서 처리한다.
- 이번 작업은 웹 레시피 검색을 제거하고 `공공 카탈로그 → 공유 추천 → Terra 생성` 순서로 연결하며, AI 생성 레시피의 선택적 공유를 추가한다. CSV 원본과 Expo 내 다른 기능은 변경하지 않는다.
- 사용자가 직접 테스트한 뒤 명시적으로 요청하기 전에는 커밋·푸시하지 않는다.

## 검색·생성 경로

1. 인증된 `menu-chat` Edge Function이 재고와 설정을 읽고 Luna로 요청 유형·메뉴 키워드·재료 키워드를 구조화한다.
2. 서버 전용 RPC가 `recipe_catalog.recipes` 이름과 `ingredients.normalized_name`, `parent_ingredient`, `search_key`에서 후보를 찾는다. `ingredients_raw`는 검색하지 않는다.
3. 공공 후보가 채택 기준을 충족하지 않으면 독립된 `recipe_catalog.shared_recipes`에서 제목·구조화 재료명으로 후보를 찾는다.
4. 후보를 채택하면 원문은 서버 내부에서만 Terra에 전달하고 사용자 재고·알레르기·도구·시간에 맞게 개인화한다. 외부 레시피 본문·이미지·웹 검색 도구는 호출하지 않는다.
5. 두 DB 모두 채택 기준에 못 미치면 Terra가 일반 요리 지식과 사용자 조건만으로 신규 레시피를 생성한다.
6. 응답은 `origin` (`MFDS`, `MAFRA`, `SHARED_AI`, `AI_GENERATED`)을 포함한다. 이 필드는 모델 출력이 아니라 서버 라우터가 지정한다. `sources`는 기존 클라이언트 호환을 위해 빈 배열로 반환한다.
7. 안전 검증 실패는 위험한 레시피를 사용자에게 내보내지 않는다. 이미 제안된 레시피 수정 요청도 같은 검색/생성 경계와 검증을 따른다.

## 후보 채택

- 메뉴명 명시 요청은 정규화 이름 완전 일치를 우선하고 부분 이름 일치는 낮게 평가한다.
- 재료 중심 요청은 보유 재료와 구조화 재료의 교집합 수·비율로 정렬한다. 넓은 요청에서 보유 재료 한 개만 맞는 후보는 채택하지 않는다.
- 공공 후보를 먼저 평가한 뒤에만 공유 추천 후보를 평가한다. DB 오류는 `후보 없음`으로 오인해 곧바로 생성하지 않고 명시적 오류로 처리한다.
- 각 검색은 최대 20개 후보를 반환하고 선택 후보만 상세를 Terra에 보낸다.

## 공유 데이터 및 트랜잭션

- `recipe_catalog.shared_recipes`는 `public.recipes`와 FK로 묶지 않는 독립 스냅샷이다. `origin_recipe_id`는 중복 공유 방지용 UUID 값만 보존한다. 개인 레시피 삭제 후에도 공유 사본은 유지한다.
- 공유 사본에는 제목, 인분, 시간, 재료명·양·단위, 조리 단계 등 재사용 가능한 정보만 남긴다. 소유자의 `ingredientKey`, 재고 여부, 구매 필요 여부, 대화 원문, 알레르기·프로필·사용자 ID는 검색 응답과 공유 내용에 포함하지 않는다.
- 공유 대상은 `origin=AI_GENERATED`인 레시피로 제한한다. 공유 RPC는 호출자의 소유권과 `completed_recipes` 기록을 확인한다. 공개 공유 데이터의 품질과 부적절한 사용자 조작을 막기 위한 입력 길이·구조·안전 검증을 적용한다.
- 요리 전 따봉 확인은 화면의 해당 제안에만 `sharePending=true`로 기록한다. 개인 DB나 공유 DB에 쓰지 않는다. 제안이 바뀌면 대기 상태를 해제한다.
- 요리 완료를 확정할 때 공유 대기 중이면 기존 차감·개인 저장과 공유 스냅샷 생성을 하나의 DB 트랜잭션에서 수행한다. 하나라도 실패하면 모두 롤백한다. 동일 요청 재시도는 중복 차감·중복 공유를 만들지 않는다.
- 완료한 개인 AI 레시피는 이후 별도 공유 RPC로 공유할 수 있다. 공유 RPC는 소유자·완료 여부를 다시 검사하며 멱등이다. 개인 레시피 삭제는 공유 사본을 삭제하지 않는다.

## UI

- 레시피 상세의 `요리 완료` 옆에 접근성 이름이 있는 빈 따봉 아이콘을 표시한다. AI 신규 생성 레시피에서만 활성화한다.
- 탭하면 정확히 `좋아요 표시를 하면 이 레시피가 다른 사용자도 이용할 수 있도록 공유됩니다.` 안내와 `취소`·`확인` 버튼이 있는 팝업을 연다.
- `확인` 후에는 노란색으로 채워진 따봉을 보여준다. 요리 전이면 공유 대기 표시이며, 요리 완료 성공 후 공유 완료 상태가 된다. 요리 실패 시 대기를 유지하고 재시도할 수 있다.
- 이미 완료된 레시피의 확인은 공유 RPC 성공 후에만 노란색으로 변경한다. 서버 오류는 기존 상태를 유지하고 설명을 표시한다.
- 공유된 레시피의 따봉은 MVP에서 게시 상태 표시다. 재차 눌러 게시물을 삭제하는 동작은 제공하지 않는다.

## 검증

- 검색 우선순위, 임계값 미달 시 Terra 생성, 웹 검색 요청 0회, `ingredients_raw` 미사용.
- 인증되지 않은 검색·공유 거부, 비소유 레시피 공유 거부, 요리 전 공유 거부, AI 생성 이외의 공유 거부.
- 요리 완료·공유 원자성, 재시도 멱등성, 개인 삭제 후 공유 사본 유지.
- UI 확인/취소/완료 전 이탈/완료 후 공유/실패와 접근성 레이블.
