# 채팅 재고 변경 승인 설계

## 근본 원인과 목표

현재 `menu-chat`은 재고 관련 발화를 `reply_only`로 처리해 문장만 반환한다. 앱은 그 문장을 채팅에 추가하지만 재고 변경 RPC를 호출하지 않는다. AI가 `차감할게요`라고 말해도 데이터는 변하지 않는다.

채팅에서 명시된 구매·추가·수령, 사용·소비·전량 사용, 남은 양 정정을 구조화된 변경안으로 반환한다. 사용자가 검토·수정·승인하기 전에는 재고를 쓰지 않고, 답변에도 완료했다고 말하지 않는다. 기존 사용자의 미커밋 작업은 보존하고 Git 커밋·푸시는 하지 않는다.

## 서버 대화 계약

- Luna 분류기에 `inventory_change` 유형과 최대 20개 `changes`를 추가한다. 각 행은 `action`(add/consume/set), 재고명, 재고 키(기존 항목인 경우), 수량, 단위, `전부` 여부를 갖는다. 명시적인 현재 발화에 근거 없는 행은 반환하지 않는다.
- `전부` 소비는 현재 사용자 재고의 해당 재료·단위 전체량으로 초안화한다. 수량·단위가 불명확하면 빈 입력란을 남겨 승인을 막는다.
- 기존 재고에 없는 소비는 변경안에서 제외하고 `등록되지 않아 차감하지 않았다`고 안내한다. 불확실한 이름 매칭은 자동 차감하지 않고 사용자가 대상 재고를 고르게 한다.
- 추가 및 재고에 없는 `남은 양`은 기존 `inventory-parse`를 거쳐 권장 소진일을 추정하며, 날짜·수량이 불확실하면 기존 검수 방식처럼 직접 수정하도록 한다.
- 변경안을 반환할 때 서버 답변은 승인 전임을 명시한다. AI 응답은 DB 변경 권한이 없다.

## 승인 UI와 재고 처리

- 채팅 응답 직후 변경안 팝업을 열어 재료명, 작업 종류, 수량·단위, 추가 품목의 권장 소진일을 편집한다. 취소 시 DB 변경 없음. 확인 필요 행이 남으면 승인 불가.
- 승인 시 사용자별 `apply_chat_inventory_change` RPC 한 번으로 add/consume/set 혼합 작업을 처리한다. 요청 키로 중복 실행을 막고 모든 변경·이벤트를 한 트랜잭션에 기록한다.
- 서버는 소유자 재고 lot을 잠그고 만료일 빠른 순으로 차감한다. 추가 후 소비가 같은 발화에 있으면 추가를 먼저 반영한다. 클라이언트 미리보기와 달리 재고가 바뀌었더라도 서버가 다시 검증한다.
- 소비량이 재고보다 많으면 서버는 변경 없이 초과 재료명·현재량을 반환한다. UI는 `<재료명>은 현재 재고보다 많은 수량을 소비했습니다. 전량 소비한 것으로 처리할까요?` 팝업을 띄운다. 취소는 검수로 복귀, 확인은 해당 행을 최신 전량으로 조정하고 다시 승인한다. 여러 초과 행은 하나씩 처리한다.
- 서버 승인 후 재고를 재조회하고 채팅에 실제 반영량을 알린다. 서버 실패 시 완료 문구를 표시하지 않고 편집안을 유지한다.

## 검증

- 발화 인식: 구매, 추가, 받음, 소비, 사용, 전부, 남은 양, 비변경 대화 및 혼합 발화.
- 승인 전 무변경, 취소 무변경, 편집 반영, 미등록 소비 제외, 초과 시 무변경·확인 후 전량 처리.
- RLS·소유권, 단위 오류, 음수·빈 수량, 중복 요청, 여러 lot 차감, 동시성·원자성.
- 웹 및 Android 동일 흐름, 게스트별 독립 재고, AI가 승인 전 완료를 주장하지 않는 답변.
